# 发烧模式

## 使用方式

- 在首页「⚙️ 更多设置」中开启「发烧模式」，默认关闭，不根据体温自动切换。
- 开启后，首页顶部显示近 72 小时内的最近体温、上次用药（药名、剂量、时间及距今时长），以及最近 4 条记录。
- 「记录体温」「记录用药」直接打开对应表单；点按近期记录可修改，「查看全部」打开现有发烧分析。
- 点击「结束模式」恢复原首页，不删除任何历史记录。再次开启时仍按近 72 小时展示，不划分病程。
- 仅提供记录展示，不计算推荐剂量或下次服药时间，也不判断是否发烧。

## 配置与兼容

- 开关单独保存在 `data/fever_mode.json`，不存在时视为关闭，首次保存时创建，无需迁移历史数据。
- `GET /api/fever-mode` 返回 `{"enabled": false}`；`PUT /api/fever-mode` 接受布尔类型的 `enabled`，其他类型返回 400。
- 首页初始化及 `GET /api/dashboard` 同时返回开关状态。不同设备刷新后立即同步，已打开的首页沿用现有每分钟自动刷新。
- 保存开关失败时保留当前展示并提示重试；保存期间禁用重复操作，过期的首页请求不能覆盖本机刚保存的状态。
- 体温及用药继续使用原有健康记录接口、校验及编辑/删除流程，不改变记录结构和药品配置。
- Docker 沿用 `/app/data` 持久化目录；部署使用 `docker compose up -d --build app`，部署不会自动开启模式。

## 验证范围

- 默认关闭、开启、结束、刷新持久化和多页面同步。
- 空记录、跨日/超出 72 小时的记录、未来时间和较长药名/备注。
- 快捷记录类型预选、保存后即时更新、修改和删除后刷新。
- 保存失败、重复点击、过期首页响应、手机及桌面布局。
- HTML 特殊字符安全显示；原喂奶、睡眠、补剂、药品配置功能回归。
