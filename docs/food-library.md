# 辅食设置（辅食库）

首页 → 更多设置 → 辅食设置（辅食库），跳转至 `/food-library` 独立页面，打开按品类分组的食物池。顶部提供“返回首页”，支持直接访问、刷新和收藏地址，不再使用首页弹窗。

首页“快速添加”的“辅食”按钮紧接“睡眠”之后，打开辅食摄入记录弹窗，不再跳转食物库。食物库独立页面仍从“更多设置”进入；记录弹窗也提供管理入口。录入规则见 `docs/food-intake.md`。

- 支持食物新增、改名、调整所属品类、删除，以及按食物名/品类名搜索和品类筛选。
- 支持品类新增、改名、修改图标和高致敏标记、删除；最多 20 个品类，非空品类不可删除。
- 食物名全库唯一，品类名唯一；名称去除首尾空白，食物名最多 50 字符、品类名最多 30 字符。
- 删除前确认；多人操作以服务端结果为准，每次打开和写入后刷新，也可手动刷新。
- 独立页面保留首页选择的深色/浅色主题，不加载首页记录脚本或启动首页轮询；页面调整不改变原有接口和数据库。
- 首次访问预置 11 个品类及常见食物，全部可修改或删除。清空后不会重新填入预置数据。
- 食物库页面只管理食物池；摄入记录和基础排敏选择在记录弹窗中处理，不在食物库展示。排敏计划、完整看板和首页排敏横幅尚未实现。高致敏标记属于品类，不代表宝宝的过敏结论。

## 存储与部署

按 PRD 使用 `${BABY_DATA_DIR}/baby-food.db`（默认 `data/baby-food.db`）。SQLite 事务处理读写，外键保护品类引用；食物及品类使用稳定且不复用的 ID。清浏览器缓存、换设备或重启服务不丢数据。

既有喂养记录继续使用原 JSON 存储，无需迁移。辅食库不进入现有 JSON 记录备份/恢复接口，也不受其覆盖；备份时需另行备份 SQLite，或停服后复制整个数据目录。运行中备份 SQLite 应使用 SQLite backup API，不直接复制正在写入的数据库文件。

Docker 构建包含 `food_library.py` 和 `food_entries.py`，原有 `data` 目录挂载无需改变。无新增第三方依赖。摄入记录随辅食库一起保存在 SQLite 中，同样不进入 JSON 喂养记录的备份接口。

## 接口

| 方法 | 地址 | 内容 |
|---|---|---|
| GET | `/api/food-library` | 返回 `categories` 和 `foods`；搜索在浏览器本地进行 |
| POST | `/api/food-library/categories` | 新增品类：`name`、`emoji`、`is_high_allergen` |
| PUT / DELETE | `/api/food-library/categories/:id` | 编辑或删除品类 |
| POST | `/api/food-library/foods` | 新增食物：`name`、`category_id` |
| PUT / DELETE | `/api/food-library/foods/:id` | 编辑或删除食物 |

非法输入返回 400，不存在返回 404，重名或非空品类删除返回 409，存储故障返回 503；错误响应含 `error`。沿用现有项目的访问模型，不新增权限体系。
