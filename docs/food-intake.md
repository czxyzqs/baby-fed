# 辅食摄入记录

## 范围与入口

按 `tempDir/需求文档.md` §5.2 实现“一餐一表单”。首页“快速添加”的“辅食”按钮位于睡眠后，打开添加弹窗；“更多设置 → 辅食设置（辅食库）”仍进入独立食物库页面。

- 日期默认为北京时间今天，禁止未来日期；今天按小时预选早餐（11点前）、午餐（11–14点）、下午茶（14–17点）、晚餐（17点后）。历史日期需手动选择餐次。
- 从现有辅食库按名称/品类搜索选择，可按品类筛选。高致敏品类显示提示，同餐同食物只能一块。
- 每块必选进食量：一勺尖、一勺、两勺、三勺、半碗、一碗；接受度可选喜欢、一般、拒绝，再点取消；备注最多500字符。
- 食物可更换，已选量、接受度、备注保留；移除食物在保存时生效。删除已有记录需确认。
- 保存整餐后首页辅食记录立即刷新，可按日期查看、编辑历史餐次，支持清空已有餐次。不影响喂奶、睡眠等 JSON 记录或原“最近记录”的统计口径。
- 食物和记录均使用服务端数据；保存失败保留表单，加载失败可重试；多设备同时编辑同餐时返回冲突，不静默覆盖。
- 点击遮罩不关闭。关闭、切换日期/餐次、重新载入、前往辅食库前，对未保存修改提示确认；刷新/离开页面使用浏览器的未保存提醒。

## 基础排敏选择及边界

未排敏食物默认“开始排敏”，也可选择“已耐受，直接记正常”。开始时创建默认3天的观察轮次；排敏中显示去重进食日期数和本次进食位次，按需求文档的勺阶预选量，可手动修改。正常食物不预选量。过敏状态支持警示、“按新一轮排敏记录”或“仅记录（误食等）”；当前页面不提供新的过敏判定入口。

记录不会因吃满天数自动标为正常。删除记录会即时减少进食日计数，但不会删除轮次历史。早于当前轮次开始日期的补记仅记摄入，不纳入当前轮次。删除辅食库食物仍保留原食物ID和名称快照，历史记录仍可编辑/删除；同名重建属于新食物，重新从未排敏开始。

本次不实现完整需求文档中的排敏队列、日历、计划预填、反应记录、完成改判、全局观察天数设置和统计页。尚无计划数据，因此不会假造计划预填或首页计划横幅；表单显示的是实际录入日对应的进食位次，而非尚未实现的计划位次P。默认观察天数固定为3天，后续设置模块接入时可扩展。

## 接口与存储

- `GET /api/entries?date=YYYY-MM-DD`：返回当天 `entries`、食物及品类选择上下文、各餐次的 `revisions`。默认日期为北京时间今天。
- `POST /api/meals`：提交 `{date, meal, revision, entries}`，餐次为 `breakfast/lunch/snack/dinner`，`entries` 中每条包含可选 `id`、`food_id`、`amount`、可选 `rating`、`note`、`mode`。
- `mode` 为 `start/normal/keep/retry/only`。已有同食物记录保持原轮次；新记录的选择与当前服务端状态不符时返回409。
- 同一 SQLite 事务中校验输入、餐次版本、食物状态及记录归属，再提交整餐新状态和轮次变化；既有记录ID及创建时间保持不变。列表遗漏的旧记录删除，空列表表示删除该餐全部记录。
- 400：字段非法、未来日期、同餐重复食物；409：版本冲突、食物已删除、记录不属于本餐或状态冲突；503：存储不可用。错误响应含 `error`。

`FoodLibraryStore.connect` 自动将 `baby-food.db` 从版本1升级为版本2，新增 `food_entries`、`food_rounds`、`food_meal_versions` 及索引，不修改已有品类和食物，不迁移或改写 JSON 喂养记录。首次初始化和升级均在 SQLite 事务中执行。旧版服务不认识版本2数据库，回滚不能只切旧镜像。

部署前使用 SQLite backup API 备份 `baby-food.db`，保存到挂载的数据目录；构建镜像包含新增 `food_entries.py`、模板和资源。回滚需停服并恢复与旧镜像相匹配的数据库备份，另行保留升级后新增数据，不能直接用旧文件覆盖运行中的库。

## 验证

项目无常设测试框架，使用隔离数据目录及临时 Playwright 脚本验证，不向正式业务库写测试记录。覆盖旧版数据库升级与数据保留、整餐增改删、快照、同日去重、历史补记、状态选择、原子回滚、多设备版本冲突、持久化、非法输入；浏览器覆盖320/390/1024px、多食物选择、数量/评级/备注、更换食物、未保存保护、加载/保存失败重试、历史编辑、浅色主题及原睡眠/辅食库入口。

2026-09-20 验证结果：25项新增接口/存储检查、28项既有辅食库检查、12组摄入表单浏览器检查和15组辅食库浏览器回归通过；Python编译及JavaScript语法检查通过。更新服务后，在390/1024px只读验证快捷按钮打开弹窗、食物选择、防误关和独立辅食库入口，无脚本异常。正式库升级至版本2，原11个品类和41种食物的内容校验和保持一致，未写入测试摄入记录；临时验证容器已清理。

本次升级前备份：`data/backups/baby-food-before-intake-20260920-171119.db`；旧镜像：`baby-app:before-food-intake-20260920`。备份使用SQLite backup API且通过完整性校验。
