# 排敏看板与排敏规划

依据 `tempDir/需求文档.md` v2.3 实现此前缺失的排敏闭环：反应记录、结果判定、排敏队列与日历排期、暂停段、首页排敏横幅、记录表单计划预填、统计与适老双模式入口。

## 范围与入口

- 首页顶部新增「排敏动态」横幅：今日计划（排敏项含 第X天/N天、今天还没吃 提示）、吃满待标记提醒；点击跳转对应页面。加载失败时横幅隐藏，不影响首页其他功能。
- 更多设置新增「排敏看板」「排敏规划」入口；两页均为独立页面（同辅食库模式），顶部提供返回首页与互相跳转。
- 排敏看板 `/screening`：五个 Tab——排敏中（进度点、今天还没吃、反应摘要、〔记录反应〕〔标记正常〕〔标记过敏〕）、过敏（逐轮时间线档案、〔重新尝试〕〔改判正常〕）、正常、未排敏（点按加入排敏队列）、统计（概览、品类覆盖、口味偏好、本月新增、过敏速览）。
- 排敏规划 `/planning`：排敏队列（↑↓ 排序、观察天数 1–14 调整、移除、从食物池添加）、⚡自动生成排期（接在现有排期之后，绕开暂停段）、一键重排未来项、月历（观察窗跨天色块、📌固定标记、暂停段斜纹、常规计划、今日高亮、过去锁定）。
- 日历移动为主交互 = 两步点选（点色块选中 → 点目标日期放下，放下即固定📌），符合适老化 BR-32；未提供拖动。
- 全局默认观察天数（1–7）在看板页设置区调整；食物级观察天数为队列项/日历区块属性（1–14）。

## 业务规则实现

- 标记过敏：症状多选 + 备注，可顺延 0–14 天自动生成暂停段（次日生效）并触发未来项重排；该食物的已排期区块与队列项自动清除。
- 标记正常适用于排敏中与过敏（改判）；重新尝试从当天开启新轮次，观察天数沿用该食物设定，历史档案保留。
- 冲突判定：不同食物的观察窗（计划区块 + 进行中轮次窗口）日期区间两两重叠即提示，不阻断；固定项与暂停段参与排期避让。
- 记录表单计划预填：本餐无记录时，当天计划（观察窗/常规计划）中尚未记录的食物自动成块；新食物默认「开始排敏」+ 一勺尖，正常食物不预选量；预填使表单进入未保存状态，关闭时走既有确认。
- 里程碑口径与既有摄入模块一致：进食日 = 当前轮次内去重进食日期；吃满观察天数不自动判定，仅横幅与看板提示。

## 存储与接口

SQLite `baby-food.db` 版本 3（`food_library.py` 迁移）：新增 `food_reactions`、`food_plan_blocks`、`food_pauses`、`food_normal_plans`、`food_queue`、`food_settings`，不改动既有表。区块食物外键 `ON DELETE CASCADE`（食物删除即计划消失，记录快照不受影响，与 BR-11 一致）。

| 方法 | 地址 | 内容 |
|---|---|---|
| GET | `/api/screening/board` | 看板数据（食物状态、轮次、反应档案、队列在列） |
| GET/PUT | `/api/screening/settings` | 全局默认观察天数（1–7） |
| POST | `/api/screening/reactions` | 记录反应（挂到最新轮次） |
| POST | `/api/screening/verdict` | 判定：normal / allergic（症状+顺延）/ retry |
| GET/POST/PUT/DELETE | `/api/screening/queue(/:id)` | 队列增删、↑↓排序、天数调整 |
| GET | `/api/screening/schedule` | 区块+暂停段+常规计划+队列+冲突 |
| POST | `/api/screening/schedule/auto` `/repack` | 自动排期 / 重排未固定未来项 |
| PUT/DELETE | `/api/screening/blocks/:id` | 移动（即固定）、天数（进行中只能延长）、取消固定；删除回队列尾 |
| POST/DELETE | `/api/screening/pauses(/:id)` | 暂停段（手动或过敏顺延生成） |
| POST/DELETE | `/api/screening/normals(/:id)` | 常规计划（仅限已正常食物） |
| GET | `/api/screening/banner` | 首页横幅 |
| GET | `/api/screening/plans?date=` | 记录表单预填 |
| GET | `/api/screening/stats` | 统计 |

错误约定沿用辅食库（400/404/409/503，响应含 `error`）。

## 适老双模式

看板与规划页右上角「A+ 大字」在 标准/老年 模式间切换，偏好按设备记忆（localStorage `elder-mode`，与主题同级的本地偏好，不入服务端）。老年模式规格遵循需求文档 BR-31：正文 20px、关键内容 22–24px、标题 26px、按钮焦点 ≥60px、行距 1.5、关键文字加粗。既有首页/辅食库/记录弹窗的适老化覆盖为后续工作。

## 已知边界

- 两个暂停段日期重叠时，日历仅显示先创建段的原因（实际使用少见）。
- 统计作为看板第五个 Tab 呈现（需求文档原为独立页面），适配本应用「首页+独立页」的导航结构。
- 静态资源版本号为服务启动时的内容哈希，本地开发改 CSS/JS 后需重启进程刷新版本。
