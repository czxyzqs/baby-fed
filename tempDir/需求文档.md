## 1. 产品概述

### 1.1 背景

宝宝自约 6 月龄起添加辅食，持续至 2 岁左右。家长的三类高频强关联需求：

1. **每日记录**：每餐吃了什么、吃了多少、爱不爱吃；
2. **排敏跟踪**：新食物逐样引入、逐日加量、连续观察数天，长期记住哪些正常、哪些过敏；
3. **提前规划**：提前排接下来的排敏顺序和菜单，且「同一时间只观察一种新食物」的约束需要被系统把关。

现有手段（记忆、笔记）无法把「新食物 → 观察 → 反应 → 结论」这条链路串起来，容易漏观察、忘结论、排期冲突。

### 1.2 产品目标

家庭自用的轻量 Web 应用：**记录 30 秒内完成；观察期系统自动算，家长只做判断；规划以「队列」维护，日历自动排开。**

### 1.3 目标用户

| 用户 | 场景 | 设备与约束 |
|---|---|---|
| **老人照护者（主要日常使用者）** | 白天喂食后随手记录、按已排计划执行 | 手机；**老花约 300 度——设备开启「老年模式」**（大字号/大图标/去手势化，§8.2） |
| 父母 | 维护排敏队列、标记结果、回顾统计（复杂操作的主要承担者） | 手机为主，电脑为辅；通常使用标准模式 |

关键场景特征：喂食时**单手操作**；日常记录者视力衰退（双模式解决，同一套数据与功能，仅视觉/交互辅助不同）；多人共享同一份数据。

### 1.4 核心价值指标（定性）

- 新食物引入后零遗漏地被跟踪至结论（正常/过敏）；
- 任意时刻可回答：「正在观察什么？已经正常吃了哪些？对什么过敏？」；
- 排敏排期冲突（观察窗重叠、出行打断）在事前被系统提醒和处理。

## 2. 总体设计

### 2.1 形态与技术架构（约束性要求）

```
手机/电脑浏览器（前端）
        │  HTTP / REST / JSON
        ▼
后端服务（Python Flask 单文件，托管静态页面 + API）
        │
        ▼
SQLite 数据库（data/baby-food.db，落盘持久化）
```

| 项 | 要求 |
|---|---|
| 后端 | Python Flask；每次写操作即时落盘，重启不丢数据 |
| 数据库 | SQLite 单文件，零配置，可整目录拷贝备份 |
| 前端 | 原生 HTML/CSS/JS，无构建工具、无外部 CDN 依赖（内网/离线可用） |
| 持久化 | 数据一律以服务端数据库为准；清浏览器缓存、换设备/浏览器不影响数据 |
| 多设备 | 同局域网手机访问 `http://<主机IP>:<端口>`，与电脑共享同一份数据 |
| 账户 | v1 不做账号登录（家庭局域网信任模型）；设置存服务端、全设备共享 |
| 部署 | 日常 `python3 server.py`；长期可部署至 NAS/常开主机/云服务器 |
| 兼容 | iOS Safari 14+、Android 微信/Chrome、桌面 Chrome/Safari/Edge |

## 3. 核心概念与通用规则

### 3.1 品类与食物

- **食物只有两个字段：名称 + 所属品类**，别无他物；
- **品类可增删改**：名称、emoji 图标、排序；非空品类需先清空食物才能删；品类上限 20 个；
- 品类带「高致敏」标记（⚠️ 角标的来源），预置 5 个：蛋类、鱼虾贝类、豆及豆制品、奶及奶制品、坚果种子类；标记本身可改；
- 预置品类 11 个（依据中国营养学会《7~24月龄婴幼儿喂养指南》与婴幼儿膳食宝塔口径）：谷薯类、蔬菜类、水果类、蛋类、鱼虾贝类、畜禽肉类、肝类、豆及豆制品类、奶及奶制品类、坚果种子类、油脂类；每类预置常见食物，无特殊待遇，均可改删。

### 3.2 排敏状态（食物的排敏标签）

状态由系统根据记录与排敏过程维护，**不作为食物属性展示在食物库管理里**，只在库以外的地方（记录表单、看板、统计、选择器）作为标签展示：

```
未排敏 ──首次引入──▶ 排敏中 ──吃满观察天数无反应──▶ 正常
  ▲                   │
  │（重来）            └─出现反应，家长标记──▶ 过敏
  └──────── 重新尝试（开启新一轮）◀──────────────┘
```

- 四态：**未排敏 / 排敏中 / 正常 / 过敏**；
- 状态可随时手动改判，全部历史档案保留。

### 3.3 观察天数（食物级属性）

- 每种食物有自己的观察天数，范围 **1–14 天**；默认取全局设置（1–7，默认 3）；
- 三处可改：设置（全局默认）/ 排敏队列项 / 日历区块编辑；
- 进行中的排敏**只能延长**，不能缩短到已吃天数以下（此时应引导标记结果）；已完成锁定。

### 3.4 两个计数口径（关键规则）

- **进食日 X**：当前排敏轮次内，该食物**有进食记录的去重日期数**。用于看板进度、完成判定；
- **今日位次 P**：`P = X + (今天在该食物观察窗计划内 且 今天还没记录 ? 1 : 0)`。用于首页横幅、记录表单的状态行与建议量。正常连续场景下 P 即「日历第几天」，与规划展示一致；中断续排后从 X 续接。

由记录推导、不单独维护计数器：补记自动 +1、删记录自动 −1、同日多次仍算 1 天。

### 3.5 排期冲突

不同新食物的**观察窗日期区间**（开始日 ~ 开始日+天数−1）有任何重叠即为冲突；同一天引入两种新食物是重叠的特例。冲突**提示不阻断**。

## 4. 业务规则总表（BR，开发与验收依据）

| 编号 | 规则 |
|---|---|
| BR-01 | 排敏状态机与改判规则见 §3.2；重新尝试 = 新一轮，观察天数沿用该食物设定，历史档案保留 |
| BR-02 | 观察天数规则见 §3.3 |
| BR-03 | 进食日 X = 当前轮次内去重进食日期数（§3.4） |
| BR-04 | 今日位次 P 公式（§3.4）；横幅/表单/建议量均用 P |
| BR-05 | 排敏中食物的建议进食量按 P：P1→一勺尖、P2→一勺、P3→两勺、P≥4→三勺（由少到多原则） |
| BR-06 | 完成判定：X ≥ 观察天数且无反应记录 → 提示「可标记正常」；有反应记录 → 展示症状摘要由家长决断：标记过敏 / 延长观察天数继续；任何时候可提前手动标记 |
| BR-07 | 记录表单状态感知追问（内联，不弹对话框）：正常→无追问；排敏中→显示「第P天/N天+建议量」；未排敏→〔开始排敏（默认）〕〔已耐受，直接记正常〕；过敏→警示 +〔按新一轮排敏记录〕〔仅记录（误食等）〕 |
| BR-08 | 计划预填：打开餐次表单时，当天计划中「尚无记录」的食物自动各成一块；同一餐同一食物只允许一块；当天已记录过的计划食物不再预填 |
| BR-09 | 同一天同一食物多次进食：记多条记录，进食日算 1 天 |
| BR-10 | 无反应不打卡，只记异常；反应症状清单固定 7 项：口周红疹/荨麻疹/呕吐/腹泻/便秘/湿疹加重/其他（「其他」建议配文字说明，不强制）；不存在「无反应」选项 |
| BR-11 | 记录是快照：删除食物不删历史记录（记录内食物名保留）；之后同名新建视为全新食物（未排敏重新开始） |
| BR-12 | 品类增删改规则（§3.1）：非空不可删、上限 20、可排序 |
| BR-13 | 进食量统一勺阶：一勺尖/一勺/两勺/三勺/半碗/一碗；排敏中按 P 预选建议量（可改）；正常食物不预选 |
| BR-14 | 接受度三档可选：😋喜欢/😐一般/🥴拒绝；仅用于回顾，不影响排敏 |
| BR-15 | 计划按天、不绑餐次；排敏计划项 = 食物 + 开始日期 + 观察天数（持续天数即观察天数，不区分两个概念） |
| BR-16 | 队列是源头、日历是投影：已开始/过去的区块锁定；手动拖过的未来区块变为「固定项📌」不再自动移动，可取消固定回归自动；其余未来区块按队列顺序自动首尾相接，绕开固定项、暂停段与进行中窗口 |
| BR-17 | 日历拖动：仅「开始日期在今天之后」的区块可拖；拖动=整块平移（天数不变）；不可落在今天及以前（自动吸附最近合法日期）；落点与其他观察窗重叠时允许放下并显示 ⚠️ 内联警告；提供「一键重排未来项」恢复首尾相接；小屏提供「点选区块→点目标日期」的两步移动备选 |
| BR-18 | 暂停段：日历手动划定（原因可选：出行/疫苗/生病/等过敏消退等，可备注）或标记过敏时自动生成；自动排期将观察窗整段绕开（排不下则顺延） |
| BR-19 | 暂停段撞上进行中观察窗时供选择：**续排**（保留累计 X，剩余天数顺延到暂停段后）或**重来**（回未排敏或重新发起，首次日期重置，档案保留）；选择依据为暂停原因（宝宝状态正常→续排；生病/疫苗/过敏干扰→重来） |
| BR-20 | 常规计划：只能选「正常」状态的食物；可跨连续多天；用中性色展示；不影响排敏排期；首页横幅裸名展示（无天数） |
| BR-21 | 未排敏食物的记录入口：队列加入（规划页、看板未排敏 Tab）；或记录时经 BR-07 追问「开始排敏」 |
| BR-22 | 未来日期不可创建记录（只能排计划） |
| BR-23 | 过去日期补记：不智能预选餐次（手动选）；预填规则与今天一致；计数自动修正 |
| BR-24 | 任意历史记录可编辑/删除，进食日与统计实时重算 |
| BR-25 | 观察窗结束后仍可向食物档案补录反应，补录时询问「是否改判为过敏」 |
| BR-26 | 月龄显示：≥1 岁「X岁X个月」、<1 岁「X个月」；未设置出生日期显示「点击设置宝宝信息」 |
| BR-27 | 设置（含宝宝信息、观察天数默认值）存服务端，全设备共享；**例外：界面模式偏好存设备本地**（BR-33） |
| BR-28 | 数据导出 JSON；导入需结构校验+二次确认后整体覆盖；清空需两次确认 |
| BR-29 | 首页横幅计划项在其计划日当天无对应记录时标灰提示「计划第P天，尚未记录」 |
| BR-30 | 统计口径：已尝试 = 正常+排敏中+过敏；品类覆盖分母 = 该品类全部食物数；接受度统计仅含有评级记录；不做与「标准/别家」的横向对比 |
| BR-31 | **老年模式视觉规范（依据工信部《APP适老化通用设计规范》+ 老花300°用眼参数）**：正文 ≥20px、关键内容（食物名/进度/横幅/按钮）22–24px、辅助信息 ≥17px、页面标题 22–28px；**可点组件焦点 ≥60×60px**（规范要求适老版 ≥60dp），关键操作按钮高 ≥60px；行距 ≥1.4（取 1.5）；关键文字加粗；对比度 ≥4.5:1；字号需**支持跟随系统缩放**（用户开系统「特大字号」时可放大至 ~30px，对应规范特大档 ≥30dp）。标准模式遵循常规可用性基线（触控 ≥44px、正文 ≥14px） |
| BR-32 | **交互去手势化（老年模式）**：不依赖长按、拖动、双击等精细手势——队列排序用明确的 ↑↓ 大按钮；日历移动只用「点选区块 → 点目标日期」两步点按；表单以点选为主、尽量少打字。标准模式保留拖动作为快捷方式，两步点选同样可用 |
| BR-33 | **双模式机制**：标准模式 / 老年模式，两套视觉与交互辅助规格、**同一套数据与功能**；切换入口 = 首次启动引导选择 + 顶栏常驻快捷按钮（如「A+」）+ 设置页；模式偏好**按设备记忆**（存设备浏览器本地，不随服务端全局设置同步——老人与父母的手机可各自固定在自己的模式）；切换即时生效 |

## 5. 功能模块详述

### 5.1 辅食库（品类 + 食物管理）

**入口**：排敏看板「未排敏」Tab 的管理按钮；设置页。独立页面。

**页面结构**：按品类分组的食物列表，每组头部为品类条（图标+名称+数量），食物行显示名称 + 排敏标签（只读，便于核对）。

**操作**：

| 对象 | 操作 | 规则 |
|---|---|---|
| 品类 | 新增 / 改名 / 换图标 / 排序 / 删除 | 名称+图标+排序；非空品类需先移空或转移食物（BR-12） |
| 食物 | 在某品类下新增 / 删除 | 删除保留历史快照（BR-11），删除前提示 |

**选择器（各处共用的食物选择弹层）**：品类横滑标签 + 搜索 + 气泡宫格；高致敏品类角标 ⚠️；未排敏气泡角标提示；支持输入自定义名称直接建库。

### 5.2 今日（首页）与摄入记录

**页面结构**：

```
┌────────────────────────────────────┐
│ ‹  9月17日 周四 · 今天           › │ ← 日期导航（未来禁入）
│ 📋 今日计划：蛋黄（第2天/3天）· 今天还没吃 ▸│ ← 计划横幅
├────────────────────────────────────┤
│ 🌅 早餐                          [＋]│
│  · 婴儿米粉  半碗 😋               │
│ ☀️ 午餐                          [＋]│
│ 🍎 下午茶 / 🌙 晚餐 …同结构…        │
└────────────────────────────────────┘
```

- **日期导航**：前/后切换 + 「今天」快捷键；过去日期可补记（BR-23）；未来日期不可进入（BR-22）；
- **今日计划横幅**：聚合覆盖今天的排敏计划与常规计划。排敏项格式（用户定稿）：
  - 持续多天：`蛋黄（第2天/3天）`（P/N）
  - 单日排敏或常规食物：`南瓜粥`（裸名）
  - 多项顿号连接：`今日计划：南瓜粥、蛋黄（第2天/3天）`
  - 当天无任何计划时横幅不显示；点击横幅跳转规划页
  - 计划日未记录标灰提示（BR-29）
- **餐次**：早餐/午餐/下午茶/晚餐 4 餐固定（自定义放 v1.1）；
- **月龄**：顶栏常显（BR-26）。

**一餐一表单（记录编辑器，核心交互）**

每个餐次卡片的「＋/编辑」打开**本餐食物编辑器**（Sheet）：

```
┌─ 9月17日 · 午餐 ──────────────────┐
│ ┌──────────────────────────┐    │
│ │ 🥚 蛋黄 [排敏·第2天/3天]   ×  │    │ ← 食物块（计划预填）
│ │ 建议量已选：〔一勺〕(按P=2)     │    │
│ │ 进食量：一勺尖 〔一勺〕两勺 三勺 │    │   ← 勺阶，建议量预选
│ │         半碗 一碗              │    │
│ │ 接受度：〔😋〕😐 🥴   备注：__  │    │
│ └──────────────────────────┘    │
│ ＋ 新增食物                        │
│                        〔保存本餐〕│
└──────────────────────────────────┘
```

规则：

1. 食物块字段：食物名+排敏标签、**状态感知行**（BR-07）、进食量（BR-13）、接受度（BR-14）、备注；
2. 计划预填（BR-08）：当天计划中未记录的食物自动成块；排敏中的块预选建议量；
3. 块操作：× 删除（编辑模式删已有记录，保存生效，计数自动回退）；点食物名换食物（量/接受度保留、状态行重算）；＋新增食物打开共用选择器；
4. 餐次智能预选（按当前时间：上午→早餐、中午→午餐、下午→下午茶、晚间→晚餐）；过去日期不预选；
5. 保存 = 整餐一次提交（新增/修改/删除 diff 提交）；底层仍为「一食物一条记录」；
6. 同餐同食物不重复；保存后横幅与餐卡即时刷新。

### 5.3 观察与结果标记

- **只记异常**（BR-10）：有进食、无反应记录 = 当天没事；不设「无反应打卡」；
- **反应记录**：入口在首页横幅计划项〔记录反应〕与看板排敏中卡片；字段 = 日期（默认当天，可选当前轮次内其他日期）+ 症状多选（7 项）+ 备注；挂入食物档案按时间线积累；
- **完成判定**（BR-06）：X 达到观察天数且无反应 → 首页横幅 + 看板同时提示「可标记正常」；有反应 → 展示症状摘要，家长决断：标记过敏 / 延长观察继续吃；
- **标记过敏联动**：食物 → 过敏，症状时间线入档案；观察窗剩余天数释放；弹「后续排敏顺延 N 天（等症状消退）」可生成暂停段（BR-18）或按原计划；
- **标记正常**：一键完成，可提前；
- **边界**：窗口结束后补录反应 → 询问改判（BR-25）；误标随时改判（§3.2）。

### 5.4 排敏看板

**结构**：四个 Tab（横滑切换，带数量角标），默认「排敏中」。

```
[排敏中 2] [过敏 1] [正常 23] [未排敏 51]
```

**Tab 1 排敏中**：食物卡 = 名称 + 品类（⚠️高致敏角标）+ 进食日进度（●●○ 即 X/N）+ 首次日期 + 反应摘要（有则警示色）+ 操作〔记录反应〕〔标记正常〕〔标记过敏〕；今日在窗内但未记录 → 卡片提示「今天还没吃」；按开始时间倒序；卡片可跳转其日历排期；空态引导去规划页排队列。

**Tab 2 过敏**：食物卡 = 名称 + 品类 + **症状时间线**（逐轮：日期+症状+备注，可展开，就诊档案）+ 操作〔重新尝试〕〔改判正常〕；按最近反应日期倒序。

**Tab 3 正常**：按品类分组的气泡墙 + 搜索过滤；点按显示首次尝试日期。

**Tab 4 未排敏**：按品类分组气泡墙（高致敏品类 ⚠️）；点按气泡 →〔加入排敏队列〕（与规划页队列同一数据）；右上「管理」→ 辅食库管理页。

### 5.5 排敏规划（队列 + 日历）

**页面结构**（自上而下）：

```
┌──────────────────────────────────────┐
│ 排敏队列（拖动排序）                    │
│ ⓪ ... ⓪ ... ⓪ ... ⓪ ...        │
│ ⓪ 三文鱼 ⚠️ 3天  ⓪ 豆腐 ⚠️ 3天  ＋    │
│                     〔自动生成排期〕    │
├──────────────────────────────────────┤
│ ⚠️ 冲突提醒区（如出现）                │
├──────────────────────────────────────┤
│       ‹  2026年9月  ›                 │
│ 一  二  三  四  五  六  日             │
│ …  [蛋黄━━第1天][第2天][第3天]         │ ← 观察窗色块（跨天相连）
│ …  [\\暂停·出去玩\\][\\暂停\\]           │ ← 暂停段（斜纹灰）
│ …       南瓜粥·苹果(常规·小字)         │ ← 常规计划
│ …  [三文鱼━━🆕][__][__]  …            │
└──────────────────────────────────────┘
```

**排敏队列**：

- 只放新食物（未排敏）；从食物池（品类分组）点选入队；长按拖动排序、可移除；队列项可单独设观察天数（默认全局）；
- **自动生成排期**：从「下一个空闲日」起（若当前有观察窗在进行，从其结束次日开始；遇暂停段整段绕开），按队列顺序首尾相接铺进日历；生成后队列清空；
- 之后新入队的食物再点生成 → 接在现有排期末尾，不动已排定区块。

**日历**：

- 月历网格；三种元素：
  1. **排敏观察窗**：彩色跨天色块（起始格 食物名+🆕，后续格 第X天），同项同色；开始日期在今天之后的区块显示「长按拖动」提示；
  2. **常规计划**：中性色小条，仅可选「正常」食物（BR-20）；
  3. **暂停段**：灰色斜纹段（原因备注可见）；
- **今天**高亮；过去/已开始的区块灰化锁定；
- **移动编排（BR-17/BR-32）**：主交互 = 两步点选——点未来区块 → 选中（高亮+顶部提示条）→ 再点目标日期放下（整块平移），放下后成为固定项📌；标准模式额外支持拖动作为快捷方式（老年模式不提供）；落点与其他观察窗重叠时允许 + ⚠️ 文字警告；提供「一键重排未来项」大按钮；
- 点区块 → 编辑面板：改观察天数（BR-02 规则）、取消固定、删除（移回队列尾部）；
- 点空白日期 → 添加常规计划 / 划暂停段；
- **冲突提醒**：顶部聚合区列出所有观察窗重叠（含与进行中窗口、与队列自动排期结果的冲突），不阻断。

**暂停段相关**（BR-18/19）：手动划或过敏标记自动生成；撞进行中窗口时弹「续排 / 重来」选择。

### 8.2 双模式与适老化（主要日常使用者为老花约 300° 的老人）

**双模式（BR-33）**：标准模式 + 老年模式，同一套数据与功能，仅视觉与交互辅助不同；按设备记忆。

**老年模式设计规范**（依据：[工信部《移动互联网应用（APP）适老化通用设计规范》](http://wza.isc.org.cn/bztx/bzjd/mobile/index.html)——适老版主要文字 ≥18dp、特大档 ≥30dp、可点焦点 ≥60×60dp、行距 ≥1.3 倍；[浙江大学眼科医院](http://www.eye-zju.cn/contents/9/3595.html)——老花 300° 约对应 60 岁+，阅读距离拉远至 30~40cm，等效字号需放大 1.5~2 倍并加粗、开高对比）：

| 维度 | 要求 |
|---|---|
| 字号 | 正文 ≥20px；关键内容（食物名、进食量、观察进度、横幅、按钮文字）22–24px；辅助/说明 ≥17px；页面标题 22–28px；日历色块内文字 ≥14px 且关键信息不只用日历小字表达 |
| 系统跟随 | 字号支持跟随系统缩放（rem 布局 + 禁用 text-size-adjust 缩放限制）；老人开系统「特大字号」时可到 ~30px（规范特大档） |
| 图标 | 图标尺寸 ≥30px；**所有图标必须带文字标签**（如「⚙️ 设置」），禁止纯图标操作；emoji 状态标签同时有文字 |
| 触控 | **可点焦点 ≥60×60px**（规范硬性要求）；「保存本餐 / 标记结果 / 开始吃」等关键按钮高度 ≥60px；相邻可点元素间距 ≥10px |
| 排版 | 行距 ≥1.4（取 1.5）；段落间距 ≥行距 ×1.3；关键文字加粗（食物名、进度、警告用 700–800 字重）；无衬线字体 |
| 交互 | 去手势化（BR-32）：点按为主，不长按/拖动/双击；队列排序用 ↑↓ 按钮；日历移动用两步点选；弹窗内选项全部为大按钮，少打字（自定义食物是唯一必要输入，输入框加大） |
| 视觉 | 文字对比度 ≥4.5:1（深色字/白底），避免浅灰小字；警示信息 = 颜色 + 图标 + 文字三重表达；高致敏 ⚠️ 角标放大 |
| 信息密度 | 单屏信息量宁少勿多；老人高频路径（今日记录）保持 2 步内完成 |
| 反馈 | 所有操作有明确的文字反馈（保存成功、已标记等大字号提示），不依赖细微动效 |
| 切换 | 首启引导选择 + 顶栏「A+」常驻按钮 + 设置页三入口；即时生效；按设备记忆 |

**标准模式**：维持 v2.0 的常规设计（触控 ≥44px 基线），两步点选与拖动并存。

> 开发验收时以「老花 300° 模拟」（如摘掉老花镜试用，或系统辅助功能缩放）在老年模式下走通记录全流程。
